## 1) R5-001（P0）— Sell 分支集中度 future_total 漏算 notional

**问题**：`04665b7` 引入 `check_concentration(..., already_reserved)` 后，`check_and_reserve` 对 **Sell 也硬编码 `true`**（`already_reserved` 仅对 Buy 成立，因只有 Buy 会预留）。Sell 不预留 → `committed_total` 不含本单 → `future_total` 漏算 Sell notional，集中度门禁（`> 2×单市场上限`）与比率被低估，与 `pre_check(.., false)` 口径不一致。

**修复**（`polymarket-rust/polymarket-rust/src/fast/risk_engine.rs`）：
```rust
// check_and_reserve —— 原: self.check_concentration(token_id, side, notional, true)
let already_reserved = matches!(side, crate::types::enums::Side::Buy);
if let Err(e) = self.check_concentration(token_id, side, notional, already_reserved) {
    if matches!(side, crate::types::enums::Side::Buy) {
        self.position_limits.release_reserve(token_id, notional);
    }
    return Err(e);
}
```

**新增测试**：`test_sell_concentration_includes_notional_in_future_total`
- 断言 `pre_check` 与 `check_and_reserve` 对同一 Sell 判定一致（均拒绝）；
- 断言 Sell 不留预留（`committed_total` 不变）。

**验证**：全量 Rust `337 + 4 + 18 + 1` 全绿；**鉴别力**：改回 `true` 后该测试必 FAILED（已实测）。

**登记**：`MASTER_TASKS.md` R5-001 追加「Sell 分支修正」；`BUG_TRACKER.md` 新增「二-D」。

## 4) R5-007（纠正）— 年化因子改用真实 timestamp

**确认**：`total_hours` 生产定义（`strategy_engine/backtest/engine.py:102-104`）=
`events[0].deadline - 48h` → `events[-1].deadline + 1h`，即**回测窗口首尾跨度**，**不是** equity 曲线首尾。

**问题**：`_resolve_periods_per_year` 旧口径 `total_hours / len(equity_curve)` 有两处错误：
1. 混用「窗口」跨度与「曲线」跨度；
2. n 个点只有 **n−1** 个间隔，却按 n 除 → 间隔被低估 → `periods_per_year` 偏大 → Sharpe/Sortino 年化被放大。

**修复**（`strategy_engine/backtest/metrics.py`）：
```python
n = len(equity_curve)
if n >= 2:
    span_hours = (equity_curve[-1].timestamp - equity_curve[0].timestamp).total_seconds() / 3600.0
    if span_hours > 0:
        interval_hours = span_hours / (n - 1)          # 优先：真实时间戳
        if interval_hours > 0:
            return (365.25 * 24) / interval_hours
    if total_hours > 0:
        interval_hours = total_hours / (n - 1)          # 回退：窗口跨度 / (n-1)
        if interval_hours > 0:
            return (365.25 * 24) / interval_hours
return 365 * 4
```

**测试**（`test_backtest.py`，均为 timestamp-based）：
- `test_sharpe_annualization_follows_sampling`：1h vs 6h 时间戳 → Sharpe 比 = √6；
- `test_periods_per_year_uses_real_timestamps_not_total_hours`：`total_hours` 传 0/999 结果不变；
- `test_periods_per_year_fallback_uses_n_minus_1`：时间戳退化时回退 `30/(6-1)=6h`（旧为 5h）。

**验证**：全量 `pytest` **111 passed**；**鉴别力**：改回 `total_hours/n` 后上述 3 测试必 FAILED（已实测）。

**登记**：`MASTER_TASKS.md` R5-007 追加「复审纠正」。

## 5) R5-009（方案 1）— daemon 子进程退出保持容器 Up

**背景**：healthcheck 断言经本地复现**正确**（`p` 为每个进程的 argv 列表，`b'-m' in p and b'market_discovery' in p` 成立；不误匹配自身）。但原 `daemon` 监督在 market_discovery 死亡时 `exit 1`，配合 `restart: unless-stopped` → 容器直接重启，healthcheck 来不及转 `unhealthy`。

**修改**（`docker-entrypoint.sh` daemon 分支）：
```bash
trap "log 收到退出信号; kill $PID_DISCOVERY 2>/dev/null; exit 0" TERM INT

# R5-009（方案 1）：子进程退出时不退出容器——保持 Up，交由 healthcheck 转 unhealthy。
EXITED=0
while true; do
    if [ "$EXITED" -eq 0 ] && ! kill -0 "$PID_DISCOVERY" 2>/dev/null; then
        log "market_discovery 异常退出；容器保持运行，healthcheck 将转 unhealthy（等待人工/编排处置）"
        EXITED=1
    fi
    sleep 5
done
```
**验证**：`bash -n docker-entrypoint.sh` 语法通过。
**副作用（已接受）**：容器不再因该子进程死亡而自动重启，需人工/编排依 healthcheck 处置。
